Part 3 - Find optimal tree depth for min deviance 0.0005 tree

To find the optimal tree depth for our fit3 tree we prune the tree to all possible amounts of leaves between 2 and 50. For each tree we record its deviance for the training and validation data. This gives the following plot of the dependence of deviances for the training and validation data on the number of leaves.

From the plot we see the deviance of the training data is always decreasing with more leaves. The deviance for the test data decreases until around 20 leaves whereafter it gets unstable. This is due to the decision tree overfitting to the training data at higher amounts of leaves. The optimal amount of leaves is gotten as follows:

optimal_leaves <- which.min(test_deviances[2:50]) + 1
print(paste("The optimal number of leaves is:", optimal_leaves))
## [1] "The optimal number of leaves is: 22"

With the optimal amount of leaves we create a optimal tree from fit3 with 22 leaves.

From the decision tree we can see that the most important variable for decision making is the outcome of previous campaigns towards a specific customer (poutcome).

In the right branch all leaves result in the outcome of the campaign being “yes”. This is a strong indicator that if a campaign has been successful before, it is likely that it will succeed again. From what can be seen in the branch it also does not matter how long its been since the last time the client was contacted.

In the left branch the majority of outcomes result in “no”. There is a single leaf resulting in “yes” when the contact is “known” and its been more than 383 days since last contact. This could be interpreted as a new customers that may not have been ever contacted before and is now receiving their first campaign call.

Part 6 - Compute TPR and FPR for a logistic regression model and decision tree

In the last part of the lab we compare the classification performance between the optimal tree and a logistic regression model using the following principle. \(\hat{Y} = \text{yes if } p(Y=\text{'yes'} \mid X) > \pi,\ \text{otherwise } \hat{Y} = \text{no}\) where \(\pi\) = 0.05,0.1,0.15, … 0.9,0.95.

For each value of \(\pi\) we calculate the true positive rate (TPR) and false positive rate (FPR) for both models. Lastly all values are inserted into a plot.

Both the decision tree and logistic regression have very similar ROC-curves. The decision tree curve is after FPR=0.6 consistently very slightly above the logistic regression curve. From these plots the performance of the two models appear to be almost equal.

A precision-recall curve is better at showing performance on predictions on the positive outcomes of a model. As previously stated our data set is unbalanced with the majority of outcomes being “no”. This means a PR curve could be more appropriate, just as F1-score is more appropriate than accuracy for our decision trees.

Assignment 4

What important aspect should be considered when selecting minibatches, according to the book?

It is very important to make sure that all different mini-batches are balanced and representative of the whole data set. If we have a big data set with a lot of different possible output classes and use mini-batches that are not balanced some of the mini-batches might not contain all of the output classes and are therefor not a good representation of the full data set. This will give bad approximations of the gradient for the full data set.
